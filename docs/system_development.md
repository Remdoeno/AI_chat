# 旺财系统开发原则

## 主系统 prompt 维护

2026-06-14 用户亲自调整了 `app.py` 中的默认 `SYSTEM_PROMPT`。后续功能修复应尊重该主 prompt，不要无意回滚或重写它；如果需要增加格式、安全、时间等工程性约束，优先放在独立的系统约束片段或专门 agent prompt 中。

## 通用解法优先

遇到线上问题时，先分析它属于哪一类能力缺口，再设计通用机制；不要针对单个例子写一次性补丁。

反例：

- 用户问高考题答错，就在代码里硬写“高考、省份、科目、考试院”等枚举。
- 用户说“回忆我们之间难忘的一件事”召回不好，就写“我们、难忘、以前聊过”等关键词触发。
- 记忆误写入 assistant 的脑补内容，就用中文子串枚举判断“某个词是否只出现在助手回复里”。

推荐做法：

- 联网搜索：用搜索规划器结合当前日期和最近会话上下文生成查询词、必需命中实体和检索意图，不按题材写死模板。
- 记忆召回：用长期记忆路由器判断是否需要回忆；需要时由 query planner 生成语义检索词。后续如果需要“全部回忆”或“某时间段回忆”，应扩展路由器输出 `recall_mode`，而不是增加固定关键词。
- 记忆写入：先由 memory agent 提取候选，再由候选验证 agent 判断该候选是否确实来自用户发言和上下文指代。assistant 的回复只能作为上下文，不能作为事实来源。
- 后台 agent 输出：memory agent 等结构化任务必须输出合法 JSON；如果模型输出被截断或格式损坏，先交给 JSON 修复 agent 按 schema 重写，不要靠本地字符串猜补事实。
- 去重与更新：新增记忆前先做相似记忆检索；重复或高度相似时优先刷新/更新已有记忆，只有明显变化、结束、纠正或新细节才写入新条目。

## 时间上下文

发给大模型的历史消息需要带上消息时间。OpenAI/vLLM chat message schema 不稳定支持自定义 `time` 字段，因此当前实现把时间写进 `content` 前缀：

```text
[message_time: 2026-06-14 10:30:00 CST]
用户消息正文
```

这样模型处理“明天、刚才、今天下午”等相对时间时，不只依赖当前系统时间，也能理解历史对话发生的时间。

## 端口约定

生产和日常部署统一使用 `7777` 端口：

- 外部访问：`http://59.66.22.107:7777/`
- 健康检查：`http://127.0.0.1:7777/api/health`

不要再把网页服务改回 `9922`。

## 长记忆精简与拆分

长期记忆应尽量原子化：一条记忆只表达一个身份、偏好、日程、diary 状态、风险或事实。不要把人物关系、生活状态、怀念、问题确认、时间线等多个信息揉成一条，否则召回时会把无关上下文一起注入 prompt。

从 2026-06-14 起，系统增加 `memory_refine_agent`：
- `memory_dedupe_agent` 负责多条记忆之间的重复、冲突、合并。
- `memory_refine_agent` 负责单条记忆内部是否过度聚拢，并在需要时拆成多条原子记忆。
- 被拆分的旧记忆标记为 `refine_status=split`，新原子记忆通过 `supersedes_id` 指向旧记忆，使旧记忆退出正常召回但保留溯源。
- 已检查但不需要拆分的长记忆标记为 `refine_status=checked`，后续后台不再反复访问。
- 新拆出的原子记忆会重新生成 embedding，继续参与普通召回、开场 prompt 和记忆库管理。
