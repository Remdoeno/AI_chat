发布日期：2026-09-17。基线：已上线的 2.8.5。

## 完整更新列表

| 独立开关 | 本次变化 | 关闭后的行为 |
| --- | --- | --- |
| 一次整理绘图提示词 `draw_single_pass` | 合并翻译、分类、优化为一次模型请求；使用统一 JSON 格式，消除多个角色指令冲突；自然请求扩展为完整英文画面，专业英文保留原文，续改保留前一张图的完整场景和比例；无效结果停止生成 | 恢复 2.8.5 的翻译、分类、优化三步流程 |
| 模型参数适配 `backend_compat` | OpenAI GPT-5/o1/o3/o4 系列使用 max_completion_tokens，避免发送不通用的采样参数；其他厂商保持各自已有协议 | 恢复原请求参数 |
| 配置预检查 `fast_fail` | 已知云模型缺少密钥、接口或型号时立即说明，避免无效远端请求 | 恢复远端接口报错 |
| 等待与重试控制 `bounded_waits` | 文本模型连接最多 8 秒、连续无数据读取最多 120 秒，原来更短的超时仍生效；取消 SDK 隐式重试，避免一次操作反复等待；持续输出的长回答可以继续 | 恢复原超时及云端 SDK 自动重试 |
| 后台结果完整性检查 `structured_guard` | 统一检查空结果、空流、输出截断，以及明确要求 JSON 的后台任务；不再把这类结果当作完成；结束、失败、取消时释放流连接 | 恢复各功能原有解析检查 |
| 可读错误提示 `clear_errors` | 区分认证、限流/额度、型号不存在、请求不兼容、连接、超时、上游故障；提示下一步动作 | 恢复原错误文本 |
| 模型连接诊断 `model_probe` | 单独诊断已保存的台前/后台模型，报告是否有正文及耗时；记录模型调用耗时和流式首字时间，不在新增诊断日志中记录消息内容或密钥 | 隐藏诊断入口并关闭新增耗时记录 |
| 聊天等待反馈 `live_feedback` | 增加已用时间，30 秒后提供停止/检查连接提示；流中断时保留已生成文字并明确标记未完成；移动端排版适配 | 恢复旧状态显示和失败回复方式 |
| 后台资源识别 `gpu_role_detection` | 以进程命令识别模型用途，避免无关环境变量导致误标；没有检测结果时完整显示配置的默认角色 | 恢复旧资源角色识别 |

### 配套整理

- 新增“3.0 体验与逐项回滚”面板，位于原模型设置内，不增加首页按钮。
- 个人开关按绑定用户保存、跨设备继承；管理员维护系统默认。个人覆盖优先，可逐项恢复继承。
- 保存即时生效于后续请求；切换用户时校验归属，防止旧弹窗写错用户。
- 诊断只使用已保存配置，不接收临时地址或密钥。个人配置无须管理员密码，系统配置仍需验证。
- 运行时策略用独立模块和组合实现，避免每个功能重复适配模型。
- 创建 2.8.5 完整代码快照及 3.0 发布快照；部署前校验基线并备份，失败自动还原代码。
- 更新旺财自我档案、版本号和静态资源缓存版本。
- 校正过期测试预期，保留旧三步流程测试，增加逐项回滚、用户隔离、模型协议、空流和错误处理回归测试。

## 怎么单独回滚

连续点四次首页兔子 → 高级配置 → 模型设置 → **3.0 体验与逐项回滚**。

关闭体验不佳的那一项即可，其余项目不变。重新开启即可恢复。选择“我的模型”只影响自己；选择“系统默认”需要管理员密码，影响继承默认值的用户。正在执行的调用不会被中途改写。

这里回退的是本次改良的行为，不会删除或恢复历史聊天、记忆、日程、会员卡，也不会关闭用户隔离和管理员验证。部分底层改良可能共同作用于一个请求，关闭一个开关不会关闭另一个开关的保护。

如需完整还原 2.8.5，应使用部署时的代码备份或 Git 标签 `wangcai-v2.8.5-baseline`，保留运行数据。不要回滚用户数据库来回退界面功能。

## 实测结果

同一服务器、相同合成输入、思考关闭，对照 2.8.5 原三步和 3.0 单次整理。下表仅为**绘图提示词准备时间**，不是完整出图时间，也不是通用聊天性能承诺。每个组合一轮，存在缓存、负载和随机输出影响。

| 模型 / 场景 | 原流程 | 新流程 | 结果 |
| --- | ---: | ---: | --- |
| Qwen / 自然描述 | 16.220s | 8.254s | 约减少 49%，两者关键场景检查通过 |
| Qwen / 专业提示词 | 17.835s | 5.487s | 旧流程错误改写；新流程逐字保留，不把旧失败算有效提速 |
| Qwen / 只改垫子颜色 | 9.932s | 4.582s | 约减少 54%，保留猫、窗户和垫子 |
| DeepSeek / 自然描述 | 4.549s | 2.168s | 约减少 52%，两者关键场景检查通过 |
| DeepSeek / 专业提示词 | 1.286s | 1.317s | 基本不变，两者逐字保留 |
| DeepSeek / 只改垫子颜色 | 4.051s | 1.517s | 约减少 63%，保留原场景 |

首次实验发现新流程指令冲突、专业分类不稳定，已修正统一提示并重跑；首次失败没有纳入提速结果。上述检查不能代表开放问题的整体准确率。

真实功能检查：两种模型均通过“先给时间地点、再给宣讲会名称”的日期/时间/地点合并，未擅自确认出席；会员卡均保留 8000 元、5 次以及归属地问题；流式算术回复均正确。所有模型实验使用隔离临时数据库，未改生产用户资料。

## 验证与限制

- 远程运行 122 项完整回归测试，全部通过；另做真实模型调用及前端 JavaScript 语法检查；不在用户本机运行测试。
- UI 的手机/桌面实际交互仍需人工体验，语法检查不能替代浏览器操作。
- 测试证明这些场景和协议符合预期，不代表模型永不出错。专业分类仍由模型判断；遇到体验退化可单独切回旧流程。
- 等待上限是单次文本调用的连续无数据上限，不是整个多步骤工作流的总耗时上限。
- 不因一次慢调用强行杀死健康模型进程。本次上线重启 Web 服务，不重启本地推理服务。
