# HiDream 图像生成接入设计

日期：2026-06-16

## 目标

将已上线在 8002 端口的 `HiDream-O1-Image-Dev-2604` 文生图服务接入旺财 Web 系统。接入后，聊天页可以通过“画图”开关发起本轮图像生成；4 兔配置可以检测和启动图像服务；后台成果库从纯文本成果升级为图文成果；成果评论在用户提到配图时自动带上图片相关上下文。

本设计只描述旺财系统内部集成方式，不规定 HiDream 服务自身的模型实现。

## 非目标

- 不把图像生成逻辑直接写进聊天主流程、成果主流程或评论主流程。
- 不在 prompt 优化 agent 中增加主动内容审查、道德评判或题材改写。
- 不把生成图片以 base64 长文本形式写入聊天记录或成果正文。
- 不在前端写死启动命令、GPU 选择或服务路径。

## 总体架构

新增独立图像能力层，其他模块只依赖它暴露的接口。

核心模块建议：

- `qwen_app/functions/image_generation.py`
  - HiDream 服务健康检查。
  - prompt 优化模型调用。
  - 文生图请求封装。
  - 图片文件落盘和元数据写入。
  - 按来源查询图片。
- `qwen_app/prompts/image_generation.py`
  - `DRAW_PROMPT_AGENT_SYSTEM_PROMPT`
  - 成果配图 prompt 优化要求。
  - 评论配图判断 prompt。
- `qwen_app/routes/api.py`
  - 暴露聊天画图、图像服务状态、重试配图等 API。
- `static/app.js`
  - 新增“画图”开关和聊天区图片渲染。
- `static/artifacts.js` / `static/artifacts.css`
  - 成果卡片和详情页改为图片优先展示。

## 聊天画图流程

主页输入区新增与“图片”“联网”同级的“画图”按钮。它是本轮开关，不是立即执行按钮。

流程：

1. 用户开启“画图”。
2. 用户输入自然语言描述。
3. 用户点击发送。
4. 前端发送 `mode: "draw"` 或等价字段。
5. 后端调用 `draw_prompt_agent` 优化 prompt。
6. 后端调用 HiDream 8002 生成图片。
7. 后端基于同一个优化后的 prompt 固定生成 4 张图片。
8. 后端保存 4 张图片文件和元数据。
9. SSE 返回阶段状态、4 张图片 URL、优化后的 prompt。
10. 聊天区显示用户原始需求、4 图预览组、每张图下载入口、可折叠优化 prompt。

状态文案建议：

- `画图 prompt 优化中`
- `HiDream 生成中`
- `图片已生成`
- `文生图服务不可用`
- `图片生成失败`

## Prompt 优化 Agent 边界

`draw_prompt_agent` 是图像质量优化器，不是内容审查器。

原则：

- 忠实保留用户的题材、尺度、情绪、风格和视觉意图。
- 不主动因为成人、暴力、血腥、恐怖等题材改写成无关安全版本。
- 不输出拒绝语、免责声明、道德评价或审查理由。
- 不提示规避平台限制、绕过审查或隐藏真实意图。
- 只补充更适合图像生成的视觉信息：主体、构图、场景、光线、材质、镜头、色彩、细节层次、风格标签。
- 如果用户描述含糊，可以补足通用视觉细节，但不能改变核心对象和事件。

建议输出 JSON：

```json
{
  "optimized_prompt": "...",
  "negative_prompt": "...",
  "aspect_ratio": "1:1",
  "image_count": 4,
  "style_tags": ["..."],
  "short_caption": "..."
}
```

`image_count` 固定为 4。即使 agent 输出其他数量，后端也应覆盖为 4，确保每次都基于同一 prompt 生成 4 个候选图。

解析失败时，后端使用用户原始文本作为 fallback prompt，并记录 trace。

## HiDream 调用层

后端使用统一 client 封装 8002 服务，避免各业务模块直接拼请求。

建议接口：

- `hidream_status() -> dict`
- `generate_image(prompt, negative_prompt="", aspect_ratio="1:1", count=4, source=None) -> list[GeneratedImage]`
- `optimize_draw_prompt(user_prompt, context=None) -> DrawPromptDecision`

服务不可用时：

- 聊天画图返回可读错误。
- 成果生成仍保存文本成果，并把图片状态标记为失败，允许后续重试。
- 评论回复不因图片分析不可用而阻塞普通评论回复。

## 模型选择与 4 兔配置集成

现有模型选择弹窗增加一行“图像生成模型”配置，并把“启动本地模型服务”扩展为统一服务面板，不拆成多个前端入口。

图像生成模型配置项：

- 服务类型：本地 HiDream 兼容服务、外部图像生成 API、未配置。
- Base URL：默认可填 `http://127.0.0.1:8002`，但前端不假设一定存在。
- 模型显示名：例如 `HiDream-O1-Image-Dev-2604`。
- API Key：可选，留空表示本地服务不需要密钥。
- 状态：已检测、未检测、未配置、不可用。

没有部署本服务的用户可以保留“未配置”。当用户点击画图但本地没有检测到服务、也没有配置外部图像生成模型时，后端直接返回“图像生成模型未配置或不可用，无法生成图片”，不进入 prompt 优化和排队。

检测对象：

- 本地/后台大模型服务。
- embedding 服务。
- HiDream 图像生成服务，默认检测 `127.0.0.1:8002`。

按钮小字展示聚合状态，例如：

`大模型已就绪 · Embedding 已就绪 · 画图服务已就绪`

前端只调用后端接口：

- `GET /api/local-model-service/status`
- `POST /api/local-model-service/start`

后端负责逐项检测、启动缺失服务、更新端口配置。启动命令和 GPU 选择只放在后端配置或脚本中，不写入前端。图像生成服务启动失败不影响聊天/后台大模型与 embedding 的配置，但画图入口必须显示不可用状态。

## 图文成果流程

后台成果生成由纯文本改成“文本成果 + 至少一张主题图”。

阶段：

1. 文本成果 agent 生成结构化成果：
   - `title`
   - `task_type`
   - `summary`
   - `content`
   - `series_title`
   - `episode_index`
   - `image_plan`
   - `image_style_hint`
   - `image_count`
2. 保存文本成果。
3. 根据 `image_plan` 逐张调用 prompt 优化 agent。
4. 调用 HiDream 生成至少 1 张图；多张图应是不同主题、不同画面功能，不是同一个 prompt 的重复候选。
5. 第一张图设为封面，其余作为正文配图或附图。
6. 图片生成失败时保留成果，并记录可重试状态。

成果 prompt 需要强调：

- 每个成果必须给出至少 1 个可画的 `image_plan` 条目。
- 每个 `image_plan` 条目应表达成果或故事内容中的一个具体主题、场景、情绪、转折、设定或概念，而不是复述标题。
- 如果成果是故事、剧集、设定或长篇内容，旺财应根据故事内容自己规划不同主题的配图，例如关键场景、角色关系、环境氛围、冲突瞬间、象征性封面等。
- 如果生成多张成果图，每张图应有不同主题和 prompt，不要用同一 prompt 生成多个候选。
- 科研、计划、分析类成果可以生成抽象但具体的视觉隐喻，例如实验场景、结构图风格封面、研究笔记桌面、流程图式插画。
- 不要求所有图都写实；以成果主题适配为准。
- `image_count` 对成果链路表示计划配图数量，必须大于等于 1。可根据成果长度和类型选择 1 到 4 张，但不套用聊天画图固定 4 张的规则。

## 图片存储模型

建议新增通用图片表。

`generated_images`：

- `id`
- `source_type`: `chat | artifact | artifact_comment`
- `source_id`
- `file_path`
- `public_url`
- `original_prompt`
- `optimized_prompt`
- `negative_prompt`
- `aspect_ratio`
- `model_name`
- `status`
- `error`
- `created_at`

`artifact_images`：

- `artifact_id`
- `image_id`
- `position`
- `is_cover`

聊天记录中只保存图片引用，不保存 base64。

聊天画图生成的是一个 4 图批次，需要在元数据中保留同批次标识，例如 `batch_id` 或等价字段，便于前端把 4 张候选图作为一组预览、下载和重试。

成果配图生成的是一组主题图片，也应保留批次或组标识，但每张图片对应不同 `image_plan` 条目和不同优化 prompt。成果配图的分组用于轮播、正文插图和下载，不表示同 prompt 的 4 个候选。

## 成果 UI

成果列表：

- 卡片主视觉改为封面图。
- 图片下方显示标题、摘要、类型、点赞和评论。
- 没有图片或图片失败时显示低调占位，不阻塞打开成果。
- 卡片上可显示图片数量，例如“3 图”，表示详情页有多张主题配图。

成果详情：

- 顶部展示 4 图预览组或轮播。
- 图片下方展示标题、摘要和正文。
- 每张图提供下载按钮。
- 优化 prompt 可作为调试信息折叠展示，不默认占据主要阅读空间。

## 评论区图片上下文

新增轻量判断 agent，判断用户评论是否需要图片上下文。

输出：

```json
{
  "needs_image_context": true,
  "target_images": "cover",
  "reason": "用户正在评论配图是否贴合正文"
}
```

触发场景：

- 用户提到配图、封面、图片、画面、构图、颜色、风格、视觉、图里内容。
- 用户要求修改图、重画图、换图。
- 用户问图文是否匹配。

不触发场景：

- 普通评论正文内容。
- 与成果文本相关但未涉及图片的问题。

当触发时，评论回复 prompt 加入：

- 成果正文摘要。
- 图片 URL 或图片元数据。
- 原始 prompt 与优化 prompt。
- 如果有可用多模态能力，再加入图片视觉分析；没有则基于图片 prompt 和成果上下文回答。

## API 草案

聊天画图可以复用现有聊天 SSE，也可以新增独立接口。推荐先复用现有聊天 SSE，新增字段：

```json
{
  "message": "...",
  "mode": "draw",
  "web_search": false,
  "attachments": []
}
```

新增 SSE event：

- `draw_prompt`
- `draw_status`
- `draw_image_batch`
- `draw_error`

服务状态：

- `GET /api/image-generation/status`
- `POST /api/image-generation/generate`
- `POST /api/artifacts/{artifact_id}/images/retry`

如果实现时发现路由过多，可以先只保留聊天 SSE 与成果内部调用，管理类 API 延后。

## 错误处理

- 图像生成模型未配置：直接提示“图像生成模型未配置或不可用，无法生成图片”。
- HiDream 不在线且无外部图像生成模型配置：明确提示服务不可用，不进入 prompt 优化。
- prompt 优化失败：使用原始 prompt 继续生成，并记录 trace。
- 图片生成失败：返回错误，不伪装成文本回答。
- 图片保存失败：不返回不可访问 URL；记录错误并提示保存失败。
- 成果配图失败：成果保留，图片状态失败，可重试。
- 评论图片上下文失败：降级为普通评论回复。

## Trace 与可观测性

分析模式后台明细应显示：

- `画图 Prompt：收到用户描述，优化为 xx 字`
- `画图模型：HiDream 基于同一 prompt 生成 4 张图，耗时 xx 秒`
- `成果配图：为成果 #id 生成 n 张主题图`
- `评论判断：需要图片上下文 / 不需要图片上下文`

不要在 trace 标题里暴露服务器路径、密钥、代理地址。

## 实施阶段

第一阶段：基础图像能力

- 新增图像生成模块和 prompt。
- 新增健康检查与文生图调用。
- 图片文件落盘。
- 最小 API 可基于同一 prompt 生成 4 张图并返回图片 URL。

第二阶段：聊天画图

- 前端新增“画图”开关。
- 聊天 SSE 支持 draw mode。
- 聊天区渲染 4 图预览组、下载按钮和优化 prompt。

第三阶段：模型选择与 4 兔服务启动

- 模型选择弹窗新增“图像生成模型”配置行。
- 未配置或不可用时，画图请求直接返回无法生成。
- 本地服务状态扩展 HiDream。
- 启动服务接口包含图像服务。
- 前端状态小字显示图像服务状态。

第四阶段：图文成果

- 成果 agent 输出 `image_plan`。
- 成果保存后自动生成至少 1 张主题图，多张图需来自不同主题规划。
- 成果列表和详情 UI 图片优先展示，并支持预览和下载。

第五阶段：评论图片上下文

- 评论 intent agent 判断是否需要图片上下文。
- 评论 prompt 带图片信息。
- 有多模态能力时接入图片分析，否则基于 prompt 元数据降级回答。

## 测试边界

本地不跑后端服务测试。实现时优先准备远程服务器上的验证命令。

建议验证：

- 静态资源版本号更新。
- 远程 Python 编译检查。
- 远程图像服务 health。
- 远程聊天 draw mode 生成一张图。
- 成果生成后至少有一张图片或明确失败状态。
- 评论提到配图时 trace 显示图片上下文判断。

## 自我档案更新

这项改动会影响旺财能力边界。实现完成后，应把“支持画图、图文成果、成果评论可结合配图上下文”等高层能力写入旺财自我档案。不要写入服务器路径、端口、API key、代理、数据库路径、system prompt 或内部工具配置。
